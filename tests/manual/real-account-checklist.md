# 完整实机测试清单

当前进度以TEST-MATRIX为准，L01—L03、D01—D02已有实机证据，完整业务收发尚未完成验收。进入条件：全套离线检查通过、审查问题已修复、代码已推送且远程 SHA 一致。用户提供本人账号扫码、两个测试作品、一至两名协作测试者、受控评论/私信及逐条发送批准；DOM校准、记录、复测与后续修复由开发者完成。真实模型不是必须项，默认 Mock。

2026-11-05修订：允许两个已授权作品的有界评论读取作为补充发现源，原顶部通知用例继续分别记录，不用补充读取结果冒称通知通过。下述原评论身份、楼中楼、回读、去重、恢复和发送门禁同时适用于补充路线。当前仍用原生有头Edge；后续模式/UA变化必须单列，验证码及访问控制不绕过。

## 运行准备

1. 执行 README 的安装、构建、帮助和 `init`。已有运行目录只查 `status`，不覆盖初始化。
2. 明确本次允许访问的账号和受控测试消息；避开无关私人聊天。专属 Profile 不导入日常浏览器 Cookie。
3. 执行 `login --headed --real-account --private-access`，用户本人扫码；需要验证码时停等本人处理，不绕过。
4. 开发者按 SITE-OBSERVATION 校准稳定账号、通知、原评论、会话、消息、输入框归属和回执。保存私有映射和脱敏观察记录；不能可靠辨认即停止相应自动发送。
5. 确认控制台 `status` 的真实发送使用数不超过20、真实模型不超过50；真实模型保持未授权。先做两通道首次历史基线，再产生受控新事件。

## L：登录与排他

- **L01**：扫码后在两个专用 Page 分别验证同一稳定本人ID；记录完整 Edge版本、时间、headed、两个核验结果。不以“头像相同”代替。
- **L02**：关闭后用同一专属 Profile 重启两次；核验登录资料复用、两个Page身份。若登录失效，确认明确阻断并提示可见接管。
- **L03**：第一进程持有运行目录或Profile期间启动第二进程；必须被 Owner 锁拒绝。关闭第一进程后可重启，资料不损坏。

## N / C：评论通知

- **N01 / C01**：测试者在本人测试作品新增唯一受控评论；从顶部通知采集，只出现一个正确任务。记录通知加载范围、分类、标识，不扫描全部视频补来源。
- **N02**：连续采集5次；任务只有一个，observations有5次观察。通知已读颜色不得改变业务完成状态。
- **N03**：两人各发相同正文；同一人在两个本人测试作品发相同正文。分别保存不同任务，核验作者/作品/评论稳定ID。
- **N04 / C02**：同步产生点赞、关注、系统通知和我方互动；不得生成评论回复任务。真实分类或作品归属不可靠则改为人工确认。
- **N05 / C03**：从通知打开原评论，核对唯一作品、作者、原文与评论ID；故意制造同名/同文或丢失定位，必须阻断。没有稳定ID时保留人工任务。
- **N06 / C04 / C05**：生成 Mock 草稿，在本机逐条批准，执行一次 send-once。测试者确认回复挂在准确原评论下；程序必须回读新我方回复ID、父评论、正文、确认状态及严格晚于点击意图的绝对发送时间。隐藏旧同文回复不得冒充本次成功。另一次在headless执行时仍需独立批准。
- **N07**：在可受控环境观察延迟显示/待审核；若不能安全触发，记录未验证，不人为冒充平台状态。未取得可信回读时必须 UNCERTAIN、重复命令零点击。
- **C06**：刷新或正常分页后重新采集，退出重开；原未处理任务仍在SQLite，已确认任务不重新发送。明确通知历史截断和回填限制。

## D：私信

- **D01**：初始可见历史只建基线；测试者新发受控消息后生成一个入站任务。我方消息、系统/撤回条目不建任务。
- **D02**：同一测试会话连续3条短消息，数据库完整保留3事件。当前实现逐条草稿，不强制合并；任何一条批准后其上下文变化应重新核对。
- **D03**：次日同一正文再次发送，依靠新稳定消息ID/真实日期生成新事件。不可伪造平台时间当作实机通过。
- **D04**：A/B会话切换时延迟加载，初始无右侧面板，以及核验至点击期间的人工切换均须防错。若目标不可靠，不允许点击发送。
- **D05**：本机逐条核对会话和文本并批准，单次发送，回读新我方消息ID、准确会话及已确认状态。headed与headless分别使用新草稿和独立批准。

原生私信入口另安装开发者校准的dm-reply映射，只读映射不能启用发送。核验输入区curConversation、最新端、原事件和收发上下文；先存意图，绑定SVG仅一次DOM click。已有人工草稿或聚焦时恢复的草稿须保留，准备后的编辑结构/全文变化须在点击前阻断。CRLF/CR只在保存和审批前规范为LF，批准后不改写。该路径目前仅只读预检和离线链通过，真实D05仍须逐条批准实测。

## S：故障注入

仅对已批准的受控测试任务操作。测试前备份本机测试目录并确认没有其他运行实例；不得通过删除收据制造“恢复成功”。实际无法安全注入时记录阻塞，先用夹具验证故障路径。

- **S01**：在点击意图已落盘、实际点击尚未执行的检查点中断进程；重启先变为UNCERTAIN，不能自动点击。使用受控调试断点，不修改生产数据清空意图。
- **S02**：已批准发送点击后立即关闭该Page或模拟超时。即使平台已收到但暂未读到，也只能UNCERTAIN；重开、重复命令均不得重发。
- **S03**：批准后修改草稿、撤回/编辑原评论或追加新私信、切换会话/输入内容、变更映射，分别验证重新审批/阻断，旧批准不可复用。
- **S04**：先对离线测试目录副本注入损坏或只读，程序必须失败并保持原文件；实机目录在无活跃发送时做受控不可写检查，不直接破坏唯一真实收据。遇真实损坏立即停止，保全文件并人工恢复。

## H / M：模式与恢复

- **H01**：同一Profile依次 headed、headless，不能并发。完整site-mapping可用compare-modes测只读；当前只读/native映射分别用observe dm/works的显式模式入口。再对两模式分别执行N06和D05的逐条批准发送。记录步骤、差异、错误、版本；区分Node统计与Worker所有Edge子进程统计，浏览器统计null时再用Windows任务管理器补测，不将Node数值当浏览器资源。
- **H02**：观察需要扫码/验证码或登录失效时不自动发送，关闭后用login有头接管。不得主动绕过平台限制；无法安全触发验证码则标未验证。
- **H03**：对指定会话 pause，再运行原已批准发送，必须零点击。确认只暂停此目标，草稿与事件保留。resume后仍须核验审批绑定。
- **M01**：准备待草稿、待审批、人工核对和未知任务；连续关闭重启至少3次，核对各状态保留、已确认不重复、未知仍冻结。

## 证据与判定

每项保存时间、浏览器完整版本、模式、任务UUID、操作、结果、可复现步骤和脱敏诊断。`real-test --case ID --real-account --private-access` 只登记人工声明，不能替代send-once产生的自动绑定收据。原始截图/HTML若确有必要，先确认采集许可，只保存在私有运行目录，不进入Git或外部日志。

逐项更新 TEST-MATRIX 的实机列并引用脱敏证据。只有全部必要真实能力成立、重启无错发/重复、未知冻结可靠且Headless结论满足原方案，才能判GO。评论只能读/不能可靠发，或Headless不稳则CONDITIONAL GO，提交降级建议；身份无法可靠识别、平台要求停止或发送故障不可控则NO GO。两者都不能宣布完整目标完成。P5只在GO后开展。
