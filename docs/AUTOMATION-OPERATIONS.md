# inbora 0.3.x 自动化迭代操作与恢复

本版本演进已有Tauri v2 + React + Node客户端。原PoC仍为CONDITIONAL GO；新自动化的真实差异与离线证据分别记录于AUTOMATION-ACCEPTANCE.md。默认不启用收取、模型或自动外发，不复用旧一次批准。

## 启动与迁移

使用当前交付清单中的安装包。第一次选择现有私有运行目录，不勾选初始化。此后客户端记住已选择目录并自动连接；短期IPC会话由已鉴权的本机父进程续期。客户端真正退出会释放Profile，不安装Windows服务或开机启动。

0.3.1将评论表情/换行正文修复与私信单会话退避合并为一次差异换包。用户正常退出当前0.3.0后，可安装0.3.1，或启动已准备的`D:\Inbora\.local\native-031-candidate\inbora.exe`；候选目录已含Sidecar和许可，不只拷贝EXE。继续使用原运行目录，不初始化新库，不清除水位或预算。此版本没有新增数据库迁移；先观察既有双通道收取，不必新发样本或重复旧发送。候选原生启动及现场巡回结果单独记入验收表。

0.3.1已由用户启动，现场多坏会话暴露对象冷却与通道退避组合的饥饿问题。0.3.2候选入口为`D:\Inbora\.local\native-032-candidate\inbora.exe`，正常退出0.3.1后再打开，沿用相同目录与双通道设置。该版本使已暂缓对象让出其它对象，保留过期失败的尝试顺序，并将聊天未打开/评论正文或编号未就绪分开显示；这次切换用于加载实际调度修复，不要求重测旧发送链。保存的退避和旧未知仍保留，不点同步、不启用模型或发送也可先观察。

首次连接自动化扩展前，以SQLite在线备份建立一致副本，验证旧表摘要、试升级和恢复后才为原库增加表。首次运行起点记录新Sidecar启动时刻，启用或账号核验较晚也不重置。升级保留原预算、基线、意图、收据、暂停和冻结。原库出现损坏或变动时停止，不删除后重建。

## 日常操作

1. 左侧“AI 与设置”的“后台收取与持续授权”显示准确本人账号及运行起点。分别启用评论和私信收取并保存。评论默认每30秒、私信每15秒有一次对应后台轮询机会；两个通道串行，每次处理一个有界窗口，人工发送优先。普通错误逐步延长间隔，默认最多10分钟；若用户设置更长间隔，则以该间隔为上界。界面展示实际读取耗时和最近成功时间。轮询不等于平台实时推送，作品/会话较多时完整巡回需要多轮。
2. 无Key、AI关闭、仅保存草稿和“暂停发送”不阻止已启用收取；切页及最小化继续。收取设置取消对应复选框再保存，只停该通道收取。全局急停停止新采集、模型和发送调度，重启不解除；确需登录或验证码时由本人在正常可见Edge处理，再显式恢复。
3. 收件箱选择任务，点击“打开人工回复”。对话框展示准确账号、会话或作品/父评论、原消息及有限上下文，后台接管续租，输入自动保存。点击一次“发送”或Ctrl+Enter确认当前全文；后台保存并绑定最新版本、只读核验资格、准备、持久意图、单次提交及回读。无需另点领取、保存或二次确认，无Key也能操作。关闭保留未发草稿，人工介入不会在关闭后隐式恢复AI；需要时明确“恢复此目标自动处理”。
4. 配置DeepSeek并保存。Key留空保存保留当前内存Key；普通业务配置不撤销持续授权。可明确勾选“在本机安全保存Key”，使用Windows当前用户DPAPI。默认关闭，未选择时重启补Key而持续授权仍保留；删除入口同时删除密文和清空内存。更换Windows用户或机器后不能假定可解密。
5. 在持续授权区核对账号、通道、模型、允许作品/会话、是否覆盖本号后续新视频/新会话、触发/排除词、回复规则、北京时间时段及次数。勾选明确授权后，选择仅启用模型或启用自动回复策略。策略范围内新任务自动生成、后端批准、单次发送及审计，无逐条聊天许可。累计MODEL50/SEND20不重置；每份策略另有额度，撤销即影响尚未存意图任务。发送额度不足时不会继续付费生成自动回复。

## 异常及恢复

作品时间精度跨起点、原生身份不明、网页保留输入、映射缺字段、平台验证、预算耗尽或未知结果会明确停止受影响动作。普通单作品失败保存对象退避并让出后续作品；账号/验证问题停止相应后台调度。已验证作品与未决链接分别保留，不让未决链接决定其它作品是否可收取。

私信单会话读取失败保留未成功的水位，120秒暂缓该对象并让出其它会话，重启仍保留；普通错误不冒充读取成功。评论文字、换行与可证明的图片表情按准确全文读取，无法证明的单行保留待核对，不中断其它评论；该质量异常及相关冲突证据在解决前阻止模型调用和发送，不用模型猜出表情补成已核验正文。

暂未取得完整回执时，新意图已在事务中登记后续任务：最多2次只读补证、每次最多30秒取消时限，单次恢复窗口120秒；正常浏览器阶段仍持有账号队列直到安全收尾，不因超时另开持有者。重启只恢复这些只读任务，已开始的模型任务转待核对，不自动重试付费调用。原意图、异常、收据及冻结保留，后续证明独立展示，不自动重发或解除旧未知。

恢复备份须先退出应用、核对不再持有目录/Profile锁，再使用保留的升级前一致备份进行私有副本恢复检查。需要恢复原库时保留当前库及全部WAL/SHM与证据，不能用回退数据库清除已消费额度或重放已提交任务。已有外发后不得直接用旧库重新运行发送；先合并当前意图/预算证据并保持暂停，由维护者核对。

2026-11-09用户已将后续GUI测试改为本人手动接管，明确不用Computer Use；本轮停止Computer Use及替代桌面自动化，替代2026-11-07的持续Computer Use授权。执行者继续自主完成后台只读核对、实现、隔离验证、审查与交付，提供最少的具体人工测试步骤。扫码/验证码仍由本人处理，此分工不扩大真实模型或外发范围。最终现场只补新增的自动发现/后台入箱、持续授权、单次业务发送、两通道规则闭环与补证差异，复用此前常规发送证据；不催办A延期样本，不重发旧未知。Windows11及额外系统兼容留后续专项。
