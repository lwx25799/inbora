# inbora 0.3.x 自动化迭代操作与恢复

2026-11-09新增额度选择：进入左侧“AI 与设置 → 后台收取与持续授权”，分别选择“模型次数无上限”“发送次数无上限”，再点“按此范围启用规则自动回复”。勾选但未保存不改当前策略。累计显示“已用／无上限”，所有已消费次数继续保留；取消无上限并保存有限总次数时，会扣除本策略继承的已用次数。Key无需重填，原账号、通道、对象和屏蔽词规则照旧。无限只解除次数门槛，关闭自动回复、撤销、急停及准确目标/单次提交/未知不重发继续有效。

同一区域的“自动回复楼中楼评论”默认开启，随策略保存生效；关闭仍收取和展示子评论，人工回复、一级评论与私信保持原策略。它控制精确子评论的自动回复，不把回复根评论当作已回复该子评论。尚未具备准确网页资格时由后台阻断并补充证据，不要求逐条添加授权。

本版本演进已有Tauri v2 + React + Node客户端。原PoC仍为CONDITIONAL GO；新自动化的真实差异与离线证据分别记录于AUTOMATION-ACCEPTANCE.md。默认不启用收取、模型或自动外发，不复用旧一次批准。

## 启动与迁移

使用当前交付清单中的安装包。第一次选择现有私有运行目录，不勾选初始化。此后客户端记住已选择目录并自动连接；短期IPC会话由已鉴权的本机父进程续期。客户端真正退出会释放Profile，不安装Windows服务或开机启动。

当前交付为0.3.5，安装包`D:\Inbora\.local\delivery\inbora_0.3.5_x64-setup.exe`，完整候选入口`D:\Inbora\.local\native-035-candidate\inbora.exe`，随附Sidecar及许可证。用户已跳过未载入的0.3.4，手动启动并连接0.3.5，原起点及MODEL1/SEND9保留，两个旧作品评论读取恢复；随后用户明确手动关闭窗口，不计崩溃。保留同一私有运行目录、原Profile、水位、额度和未知记录。新视频/新入站与自动回复闭环仍待实机证据；后续小修使用下述开发模式，不再次安排升版换包。启动后由后台自动收取，无需点同步；错误退避保持，不通过清除状态催跑。

单账号连接后自动使用原专属Profile的无头浏览器，在应用运行期间持续保持原持有者。正常重启恢复在线，不重置采集起点或许可；用户关闭自动回复仍保持关闭。普通浏览器关闭以无头重连，失败有30秒退避；身份变化、登录/验证码、平台停止及全局急停不会被普通重连清除。真正退出停止采集并释放持有者。

只有需要本人登录或登录验证时，在左侧“AI 与设置 → 回复模式与运行”点“登录或处理验证码”，临时打开可见浏览器。期间保留收取配置、持续授权、人稿、Key与累计额度，暂停收取/补证/模型/发送；后台最多每30秒核对一次两页的绑定本人身份和空编辑器，成功后自动回无头。扫码后直接关闭登录窗口也只会以无头重开并核验；未登录或身份不符不恢复业务。“返回无头运行”是可选退出入口，不是登录完成的必要步骤。有网页人稿时保留输入并阻止关闭，不强行丢弃。CLI普通命令默认无头，`--headed`仅供login；旧compare-modes禁用，历史证据保留。

首次连接自动化扩展前，以SQLite在线备份建立一致副本，验证旧表摘要、试升级和恢复后才为原库增加表。首次运行起点记录新Sidecar启动时刻，启用或账号核验较晚也不重置。升级保留原预算、基线、意图、收据、暂停和冻结。原库出现损坏或变动时停止，不删除后重建。

无限额度使用automation_schema 3；升级前一致备份位于原运行目录的backups中（`automation-before-*.sqlite`，确切文件由本机交付清单记录）。旧安装包不支持新增模式时会拒绝连接，不能直接用旧包覆盖或重建当前库。恢复先退出持有该运行目录的客户端并保留当前库完整副本，再按明确回退决定恢复已验证备份；回退会回到备份时状态，不默认执行。私有副本已验证升级和精确恢复，原Profile、密钥安全存储和当前数据独立保留。

## 开发调试与后台重载

本轮后续优先使用`pnpm desktop:dev`。前端在回环地址127.0.0.1:1420热更新或自动刷新，Node的src源码保存后只安全重载Sidecar；只有Rust或原生配置变化才由Tauri重编原生部分，不为普通界面/后台小修重打安装包。开发窗口使用独立identifier `app.inbora.development`及`.local/desktop-dev-webview`，不替换正常0.3.5制品。隔离的实际原生开发QA已验证后端重载、人稿保护、CSS热更新及正常退出，真实账号差异另列。连接真实运行目录仍须遵守单持有者锁，不能与另一个已连接实例同时占有。

本机可见续调入口为根目录`D:\Inbora\启动inbora.cmd`，转入`.local\start-development.cmd`。入口仅在自身进程设置已核验Rust/MSVC工具链和本轮已授权的原运行目录，不修改全局配置、不创建安装包。调试窗口即使使用独立WebView记忆，也自动连接这个固定目录，不要求首次重新填写；仅debug原生接口读取该绝对路径，正式包仍沿用已有目录记忆。已有成功连接优先，不再次connect；明确未连接时原生指定目录优先于WebView旧记忆，initialize固定false。后台暂未ready只对固定RESTARTING提示最多20轮/250毫秒重读状态，不重试connect；失败保留准确目录和固定提示，不创建新库或重放业务。新增实际原生冷启动已在全新合成WebView验证无需点击即连接及正常退出，不代替真实账号的收取/策略证据。

后台重载先关闭旧子进程输入，等待已接受的连接安全收尾、应用服务取消任务并释放锁，旧进程正常退出后才启动下一代；没有强杀超时或第二持有者兜底。重载期间的新命令立即返回固定提示，不排队。新后台只重连此前成功连接的规范目录；前端读取权威状态、重新绑定当前目标并保留未保存人稿，不自动重放保存、模型或发送。已就绪子进程异常退出时保持不可用，先查明原因再重新启动开发后台，不自动循环重启；新子进程在ready前遇到语法错误时，修正源码后可恢复，不把记忆的目录误当作它已经持有的目录。

默认内存Key会随后台重载丢失，需在“AI 与设置”补填；明确选择Windows当前用户DPAPI保存的Key可由新后台重新读取。持续授权、原始起点、累计额度及自动回复开关保留，不因补Key重新批准或重置额度。已存意图只继续原合同允许的只读回读，未知不重发；仍在编辑的人稿要在恢复后继续输入才触发新的自动保存，不用旧回调覆盖它。

## 日常操作

1. 左侧“AI 与设置”的“后台收取与持续授权”显示准确本人账号及运行起点。分别启用评论和私信收取并保存。评论默认每30秒、私信每15秒有一次对应后台轮询机会；两个通道串行，每次处理一个有界窗口，人工发送优先。普通错误逐步延长间隔，默认最多10分钟；若用户设置更长间隔，则以该间隔为上界。界面展示实际读取耗时和最近成功时间。轮询不等于平台实时推送，作品/会话较多时完整巡回需要多轮。
2. 在左侧“AI 与设置”顶部使用统一“自动回复：开／关”，顶部栏是同一个控制。开启后按已保存账号/通道范围回复全部新评论和私信，仅屏蔽词命中时不自动回复；无需触发词或逐会话交接。关闭停止新的自动生成及尚未提交的策略发送，账号在线、双通道收取和人工回复继续；已提交消息继续回读及有界只读补证。重开沿用同一策略及剩余额度，关闭选择重启保持。无Key、AI关闭、仅保存草稿也不阻止收取。全局急停位于设置故障处理，停止全部调度并持久保留，显式恢复前重启不解除。
3. 私信每个准确会话一行，选中直接显示聊天和回复输入；查看不暂停自动回复，输入框聚焦或继续输入时自动接管、续租、保存。切换页面或目标前保存并释放编辑，旧人稿保护在其原消息，不永久暂停整个会话；正在编辑的租约仍优先于AI。同昵称不同会话分开，“加载更早消息”读取本地历史。评论保留作品/父评论并以“打开人工回复”进入对话框。点一次“发送”或Ctrl+Enter确认当前全文，其余保存/资格/版本/准备/持久意图/单次提交/回读由后台完成，无Key可人工操作，不另点领取、保存、继续或交回。
4. 配置DeepSeek并保存。Key留空保存保留当前内存Key；普通业务配置不撤销持续授权。可明确勾选“在本机安全保存Key”，使用Windows当前用户DPAPI。默认关闭，未选择时重启补Key而持续授权仍保留；删除入口同时删除密文和清空内存。更换Windows用户或机器后不能假定可解密。
5. 首次在“后台收取与持续授权”设置账号、通道、模型、作品/会话范围、后续新视频/收件箱覆盖、屏蔽词、回复规则、时段及额度，点“按此范围启用规则自动回复”一次。AI根据每条原文及同一目标有限上下文生成回复，回复规则描述账号口吻和业务要求，可自行填写；默认不套固定模板。策略包含模型许可，无需另外启用仅生成建议。改规则保留已消费预占，不重新算满；旧含触发词的策略保留原范围，GUI保存新范围后才变更。有效次数上限以已保存策略为准，支持明确选择无上限；20:52已保存版本4无限策略，累计MODEL7/SEND13保持，以界面实时值为准。有限额度不足不继续生成，关闭、撤销及急停仍有效。

收件箱只显示“等待回复”“已回复”。待处理、人工复核、在途及未知消息均保留在等待回复，不藏到另一技术筛选；确认送达或追加完整后续证明才显示已回复，后来矛盾优先显示等待。底层原意图、收据、冻结和审计不改写，未知不重新发送。消息原文及评论父子关系保留，原生编号放在可展开消息信息；领取、保存、核验和二次确认不是日常步骤。

图片/表情预览由原专属浏览器在正常收取窗口内生成本机受限PNG，再按准确消息授权读取；不会把URL交给前端、下载原始媒体或送给模型。未加载、视口外、遮挡、未映射卡片或校验变化保留不可用说明，不用通用占位假称已显示。缓存沿用运行目录证据保留期（默认14天），最多500清单/80MiB，可重建，不等同永久媒体归档；当前真实媒体显示和纯媒体人工回复资格仍分别见验收表，不把已保存图片类别冒充可发送资格。

分享视频或图集优先显示准确作品链接及“复制视频链接／复制图集链接”，不把封面当图片消息。链接来自准确原生分享对象或唯一可见原生链接，旧事件绑定保留；只有用户点击复制才写剪贴板，不自动打开、播放或下载。后台下一轮会为选中的缺展示资料媒体读取一个有界窗口，随后回到正常巡回，保持原成功水位与历史续查；同目标120秒冷却。正文未就绪或目标无法核验时继续保留原因，不猜作品ID或重新发送消息。

已核原生分享即使封面或卡片暂未渲染，也可按准确消息及作品引用补齐链接，保留旧弱质量事件。未知分享类型或普通文字尚未挂载继续退避并显示必要原因；不以模型猜内容，也不重新创建历史任务。消息预览失败只显示一条中性状态，不能从失败提示推定它是图片。

媒体及分享消息允许人工查看后直接输入并点一次“发送”，无需生成AI建议。后台重新核验准确原消息与媒体/分享结构，绑定最新人工全文、版本、选择和接管；原生消息无法定位、网页已有草稿、证明变化或过期时保留人稿并停止提交。该人工资格不会开启媒体AI理解或自动回复；原未知仍冻结且不得重发。历史/AI来源草稿须经实际人工编辑后才可用于媒体回复，不能把旧来源自动标成人工。

## 异常及恢复

作品时间精度跨起点、原生身份不明、网页保留输入、映射缺字段、平台验证、预算耗尽或未知结果会明确停止受影响动作。普通单作品失败保存对象退避并让出后续作品；账号/验证问题停止相应后台调度。已验证作品与未决链接分别保留，不让未决链接决定其它作品是否可收取。

私信单会话读取失败保留未成功的水位，120秒暂缓该对象并让出其它会话，重启仍保留；普通错误不冒充读取成功。评论文字、换行与可证明的图片表情按准确全文读取，无法证明的单行保留待核对，不中断其它评论；该质量异常及相关冲突证据在解决前阻止模型调用和发送，不用模型猜出表情补成已核验正文。

私信每轮补收一个有界窗口，续查状态持久保存；补收未完成不更新成功时间，重启恢复不重放任务。历史位置恢复先探测物理两端，高度变化重新定位，不把首次基线前历史变成新待办。后台评论在准确作品、唯一列表且网页输入为空时自动滚入列表；网页已有输入会保留并停止该操作。

剩余读取失败由后台在原授权组件内自动记录一次结构化几何报告，每个collector每通道至多一次，文件名`evidence/collection-read-*.json`。只含数量、位置、布尔与固定枚举，无正文、输入值或原生编号；返回失败另限定唯一映射控件最多12节点，事件字段仅检查函数是否存在，不执行处理器/getter。不要求用户打开开发工具或重复截图。报告失败不覆盖原始失败原因、不推进成功水位，也不放宽发送条件。

0.3.5的返回诊断已定位到映射DIV中心的子SVG持有点击事件。新增源码在相同门禁内点击实际中心命中元素一次，仍等待聊天隐藏；尚未加载到真实账号，不通过再次点击或改选择器绕过失败。后续在开发模式补这一处差异，不要求重测旧发送链。

暂未取得完整回执时，新意图已在事务中登记后续任务：最多2次只读补证、每次最多30秒取消时限，单次恢复窗口120秒；正常浏览器阶段仍持有账号队列直到安全收尾，不因超时另开持有者。重启只恢复这些只读任务，已开始的模型任务转待核对，不自动重试付费调用。原意图、异常、收据及冻结保留，后续证明独立展示，不自动重发或解除旧未知。

恢复备份须先退出应用、核对不再持有目录/Profile锁，再使用保留的升级前一致备份进行私有副本恢复检查。需要恢复原库时保留当前库及全部WAL/SHM与证据，不能用回退数据库清除已消费额度或重放已提交任务。已有外发后不得直接用旧库重新运行发送；先合并当前意图/预算证据并保持暂停，由维护者核对。

2026-11-09用户已将后续GUI测试改为本人手动接管，明确不用Computer Use；本轮停止Computer Use及替代桌面自动化，替代2026-11-07的持续Computer Use授权。执行者继续自主完成后台只读核对、实现、隔离验证、审查与交付，提供最少的具体人工测试步骤。扫码/验证码仍由本人处理，此分工不扩大真实模型或外发范围。最终现场只补新增的自动发现/后台入箱、持续授权、单次业务发送、两通道规则闭环与补证差异，复用此前常规发送证据；不催办A延期样本，不重发旧未知。Windows11及额外系统兼容留后续专项。

0.3.5已合并持续增长会话的公平轮转、原生ID锚定续查，以及已映射可见媒体的待人工消息保留。媒体验证只保留固定说明及原生身份，不把说明当完整正文用于模型或发送；正文加载中继续后台等待。交付范围与状态以验收表和私有制品清单分别核对，不用源码提交或合成原生QA替代真实账号运行证据。

合成原生QA使用独立identifier、WebView数据目录与运行根，预置停止避免打开真实网站；调试仅监听回环地址。正常包先归档并核对哈希，再构建QA版本，不能把QA覆盖后的共用release输出当正常制品交付。QA结束核对自身进程、端口和合成锁释放，保留用户当前实例。
