# 知识与回复人格

本功能在已有单账号客户端内，将知识事实、本人回复风格和当前会话上下文分开管理。通过本地检索、可编辑人格规则及少量已采纳样例改善回复，不训练或微调模型权重。入口为左侧收件箱下方的「AI 与设置」→「知识与回复人格」。

## 使用顺序

1. 在「知识库」新增条目，或导入 TXT、MD、DOCX、文字 PDF、CSV、XLSX。核对提取文字、主题、适用通道和有效期；保存默认为停用，明确启用后才用于回复。修改已启用条目会重新停用，需核对再启用。
2. 在「聊天样本」查看本机已确认回复候选，或导入 TXT、CSV、JSON、JSONL。TXT 每行使用 `发言人: 正文`。表格或 JSON 映射发言人、正文、可选会话及时间列，填写本人名称，先看问答配对再确认导入。时间列接受带时区的 ISO 时间或 10/13 位 Unix 时间；不选则按原始行顺序。
3. 明确采纳适合学习的本人回复。来信只作为问题上下文；群聊、无法确认本人、纯 AI 自动回复和敏感/指令污染样本不能直接成为人格教材。连续本人消息合成同一回复，过长问答整组略过。未采纳的候选不会自动进入模型。
4. 在「回复人格」同意发送所选必要片段并开始学习。模型先分批提炼，再合并为本地草稿；可修改草稿、发布，或重新发布旧有效版本回退。失败任务可显式续作，已成功批次复用；不自动重试付费请求。
5. 在「试聊」输入模拟来信，选择人格和知识来源。可用「仅现有账号人设」作为基线，与候选人格比较。单人格一次调用，对比两次；此处不产生发送意图，也不打开抖音页面。

原生路由增加了 `replyKnowledge`。已经打开的旧开发窗口需关闭后从项目根目录 `启动inbora.cmd` 重开一次，开发启动会按需重编译原生层。无需重新选择运行目录、安装或切换安装包。关闭前保留正在编辑的内容；原有退出流程等待在途业务收尾。

## 数据及调用边界

- 数据保存在既有私有运行目录的 SQLite 中；临时上传在同目录 `reply-imports`，导入/取消/正常关闭时删除，异常遗留按 24 小时清理。原文件不会复制进 Git。
- 知识是事实来源；样例只描述表达方式，不建立联系人长期记忆。本人事实应作为用户确认的知识单独录入。号码、邮箱、链接会脱敏；含数字事实、明显身份及承诺的样例不用于风格示例。规则过滤不等于完整匿名化，仍需人工检查所采纳文字。
- 自动采集只读取已存在、准确绑定且已确认的回复；每轮最多推进 500 条，并保存处理记录。稍后核验成功的旧意图仍可收录。删除的来源不会因同一发送意图被下轮采集重新注入。后续主动发言目前不作样本，因为旧锚点不能证明其紧邻问题。
- 候选采集不消耗模型额度；人格分析、合并、单次试聊与对比分别记录用途，共享现有模型授权和累计预算。没有新增服务、Key 或独立收费通道。正式自动回复仍受现有开关、账号、范围、时段、额度及唯一发送协调器约束。
- 单文件 20 MiB，待处理批次 100 MiB；48 KiB 分块经过原生鉴权管道传输。解析在 Worker 中运行，30 秒、192 MiB JS 堆上限；压缩内容声明上限 100 MiB、PDF 500 页、表格/聊天最多 100,000 行。扫描 PDF 无 OCR；公式单元格留空并提示。Worker 的 JS 堆限制不是整个进程的硬内存上限。
- 人格分析最多 200 组、5 批，每批最多 40 组及 12,000 字符，再进行一次合并；已选择的超长内容整组省略并报告数量。多会话样本约 20% 按完整会话保留为评估集；只有一个会话时没有独立留出集。留出不代表已完成质量评测。
- 检索采用 SQLite FTS5 三元索引及中文二元词项，无向量服务。最多保留 20 个候选；进入模型的知识最多 4 段/2,400 字符，风格样例最多 3 组/1,200 字符，人格最多 2,000 字符。同主题不同有效内容按冲突处理，阻止直接生成。主题需要维护；系统不能识别所有跨主题语义矛盾。
- 无知识命中时沿用账号配置和准确会话上下文，提示词要求缺少必要事实时澄清；这不能确定性证明所有事实齐全，也不保证任意知识缺失都会自动转人工。发布前仍需用实际问题核对事实与语气。
- 检索耗时超过 500 ms 时拒绝其结果进入模型。SQLite 同步查询不能在 500 ms 当场中断，因此这是结果时限门禁，不能宣称硬实时取消。
- 每次回复保存实际知识/人格选择的指纹；模型返回、恢复旧草稿、保存建议和最终发送意图前重新核对。来源被删除、相关版本改变或增加相关冲突会阻止旧草稿发送；无关知识修改不使其失效。已经持久化的发送意图继续原有回读，不因知识修改重发。
- 来源删除会撤销其样本、相关人格和学习任务；生成见证保留必要 ID/摘要，不保留知识和样例正文。历史发送、原始会话、已生成草稿及一致性备份有各自用途，来源删除不等于擦除这些独立记录或备份。
- 当前本地助手 MCP 授权不自动扩展为访问整份新语料；知识管理及显式学习从 GUI 进入。GUI 建议及正式自动回复接入已启用知识与已发布人格。

## 实施与验证记录（2026-11-16）

扩展使用主库 schema3 的附加表，知识扩展独立版本为 3。迁移先一致性备份、私有副本试升级、恢复核验，再事务升级原库；清单核验按行流式哈希，支持既有 FTS 无 rowid 表。开发源码监视器在实现期间自动加载过扩展版本 1/2，因此保留了 1→3、2→3 的正式升级路径及恢复备份。未将开发阶段升级当作正式安装包验证。

已验证范围包括：格式解析与分块次序、明确映射和重复导入、管理权限与无授权零调用；来源去重/删除/版本、知识有效期和冲突、中文检索、10 万样本检索路径；学习精确选择及失败续作、基线对比、额度、敏感信息、模型在途配置变化；实际 ClientService 的建议保存、自动稿恢复和最终发送意图门禁；合成浏览器四个界面的交互和窄窗口布局。合成测试不连接真实平台，不调用付费模型或发送真实消息。

运行过既有回复链路 125 项定向回归，以及单元/知识集成联合 323 项检查；上述数字对应当时各次运行，存在重叠，不能相加。知识功能联合 7 个文件、50 项测试全部通过；最后修正历史人格试聊和对比撤销竞态后，数据 13 项及模型/生成 19 项差异回归通过，新增测试总数为 51 项。最终旧回复/MCP/提示词边界回归 4 个文件、86 项通过。干净生产依赖安装、SQLite 写入后重开、源码 Worker 与纯构建 Node Worker、TypeScript、Node/Web 构建及原生 `cargo check` 分别验证。源码检查 462 个文件，最大为 799 行。未构建安装包，未进行真实原生窗口交互验收。

验证中发现并修复了 XLSX 用户列被元数据覆盖、JSON 长数字精度、导入启动并发容量、解析 Worker 继承主进程参数、关闭等待 Worker、未知命令字段未拒绝、样本与人格分页、历史版本/基线对比、最终对比结果撤销及在途配置变化等问题。最终的上述检查均基于修复后代码。干净运行首次因工作目录错误失败，修正后才进行构建链验证，不记作首次通过。最后数据单文件测试结束出现 Vitest worker 终止超时提示，断言全部通过、退出码 0、数据库及夹具已关闭清理；该提示不当作业务失败，也不隐去。

用户只需补一次差异验收：重开开发窗口后，导入一份本人选定的小样本，核对配对、采纳并学习；用未参与学习的真实问题比较基线与候选，确认事实正确、语气相似后发布。此验收不要求重复旧评论/私信发送链路。尚未完成本人语料的人格效果评定，也未宣称已训练出满意人格。
