开发顺序：M1 交付可浏览编辑客户端：单账号状态、评论/私信收件箱、筛选分页、准确目标与有限上下文、空白人工草稿、设置及审计；M2 补齐统一人工回复：操作员鉴权、目标接管、草稿版本、持久幂等命令、通道能力、暂停和急停；M3 交付独立 DeepSeek 适配、凭据与预算、sidecar 生命周期及 Windows x64 原生启动包；M4 在原授权范围内完成 GUI 纯人工与 AI 辅助的评论、私信实机试用，故障恢复及最终报告。按可运行切片推进，M3 的独立准备可并行，不因依赖阻塞闲置其他工作。

界面交付：按方案采用浅色客服收件箱，左侧账号与运行状态、中间双通道待办、右侧准确目标/上下文/编辑器，设置与审计在同一窗口。900×640 和 1240×800 均可用，长文可滚动，完整目标和批准全文可检查；评论展示作品、父评论、作者和回复关系，不伪装成私聊。无需 AI 草稿也能输入、保存、清空和明确确认发送；AI 建议可引用、编辑、拒绝。显示实际发现来源、最近成功同步、接管人、版本、禁用原因和内核权威状态；不伪报实时在线。日常浏览、编辑、审批、发送、暂停及查看结果无需 CLI；扫码和平台验证保留正常可见浏览器接管路径。

架构与合同：React → Tauri 受限且鉴权的 IPC → Node 应用服务，CLI 和 GUI 共用现有数据库、ProfileOwner、AccountActor、适配器和唯一 SendCoordinator。前端不直接访问 Playwright、Profile 或 SQLite，不另建采集/发送逻辑。按现有职责增加 src/app、契约及 desktop，不搬迁重写全仓。Node 签发当前本机操作员会话和权限，不信任前端 operatorId；接管按 accountId/channel/targetKey 持久化，租约120秒、编辑时每30秒续租，接管/释放/账号暂停递增 generation 并使未点击旧审批失效。人工保存用 expectedVersion；AI 迟到只能成为候选，不覆盖新人稿；批准绑定准确目标、全文、草稿/上下文版本、接管代际和操作员。一次确认使用稳定 commandId，重复点击/IPC/重连同ID同参数返回原结果，不同参数拒绝；与发送意图事务关联，版本变化不能绕过已有发送。重连取权威快照，不自动重放提交。

模式与能力：只实现 OBSERVE、DRAFT_ONLY、MANUAL、AI_ASSISTED，不实现 LIMITED_AUTO。首次接入或能力未验证强制 DRAFT_ONLY；Node 按账号、通道、浏览器模式保存 READ_OK、SEND_REVIEW_ONLY、SEND_AVAILABLE、BLOCKED 及证据与有效期，初始24小时，账号/映射/浏览器版本变化或安全验证使能力失效。前端切换模式不能开通发送，评论和私信独立启用；受控校准另设显式入口，不绕过授权。排队后与意图前重新核验全部门禁，切换目标使旧预检失效；等待超过60秒或唤醒失败退回重新确认并保留草稿。

发送与恢复：逐条明确确认准确目标和完整文本，沿用单账号串行、点击前持久意图、同一浏览器同步任务最终核验、一次提交及可信回读；不以HTTP200、输入框清空或点击成功判送达。保留现有严格时间/完整请求因果证明合同，收据矛盾继续暂停。急停通过独立控制路径，不排在浏览器或模型长任务后；未存意图的发送失效，已存意图继续回读或冻结，不能伪报撤回。未知仅只读核验，不实现 MARK_NOT_SENT 解冻、一键重试或扩展旧重试授权。数据库显式版本迁移先在私有副本验证备份、升级及恢复，保留基线、水位、暂停、预算、审批、意图、收据和异常，不清库重测。所有本项目浏览器自启动即静音。

DeepSeek：先核对当时官方文档、用户可用模型和现有服务，按真实 Chat Completions 的 messages/choices/usage 独立适配，不能把旧自定义 HTTP Provider 换地址冒充兼容。按方案非流式、输出上限512 Token、30秒超时、无自动重试；调用前持久预占累计预算，有限同目标上下文、敏感信息阻断及输出验证继续生效。仅用户显式请求才生成建议，保存/编辑不调用模型，失败后仍可人工处理。Key 输入后交给后端并清空界面，默认仅后端进程内存持有；非密钥配置存私有目录，“记住密钥”只有 Windows 凭据存储/DPAPI 落实后才可提供。选供应商或填Key不等于调用授权；沿用现有模型50次/发送20次累计上限，不重置用量、不复用已消耗的发送批准。
