## 实机授权后由开发者完成

1. 在应用专属 Profile 扫码，分别检查两个 Page 的稳定本人账号标识、登录失效、验证码和平台停止提示。
2. 观察顶部通知入口、弹层、可见行、分类、时间、作品/评论/作者稳定标识、跳转链接以及明确回复区；没有展示的字段保留 null。
3. 测量通知可见时间范围、当前加载数、总数是否可知、分页/截断/保留期；不使用全量作品评论扫描补齐缺失来源。
4. 观察私信入口、会话列表稳定 ID/对方稳定标识、右侧活跃会话/对方标识、收发方向、消息稳定 ID/绝对时间，以及可见历史范围。只有相对时间或精度不足时标记人工核对，不伪造精确时间；新增旧历史不能作为新任务。
5. 对原评论和私信输入框分别证明归属，核对左侧活跃会话与右侧会话/对方均一致。观察发送后新出现的我方稳定消息/回复 ID、正确父评论或会话、确认/待审核状态与可核验绝对发送时间；必须严格晚于持久意图边界，隐藏旧同文消息不能作为新收据。无法证明时冻结为UNCERTAIN。
6. 将已观察字段写入私有 `site-mapping.json`。字段可以是相对 CSS selector 的文本/属性，也可以对实际暴露的链接使用显式正则提取；不得以固定文本伪造网页未暴露的 ID。
7. 对映射运行本地校验和真实只读检查后，记录版本、观察时间、脱敏证据引用、无法可靠确认的字段和阻断原因。缺失稳定身份或可信回执时保留人工辅助模式。

映射 schema 为 `src/config/site-mapping.ts`。`tests/fixtures/site.ts` 的 data 属性只属于合成页面，不能当成抖音选择器，也不能把其 environment 改名后用于真实发送。真实模式同时要求 `environment=douyin` 与准确 HTTPS origin。

### 参考源码后的有界渲染字段校准

- 按用户要求核对原方案开源候选后，发现DSH在当前渲染组件的固定props路径读取消息元数据。独立只读探针在受控聊天头部和三个精确文字气泡上验证成功：三个不同服务端消息ID、同一原生会话ID、同一发送人及绝对创建时间实际存在；正文与气泡一致，消息会话与头部一致，时间均晚于先前私有历史基线。该结论补充了此前“HTML属性未见ID/时间”的观察，不能把两者混为网页整体字段缺失。
- 探针只读取固定路径的数据属性，拒绝getter和冲突描述符，不执行网页方法、不遍历全应用状态、不调用平台私有协议。实际ID、时间和消息快照只留私有目录；正式适配器、审批、真实提交与回执仍未完成校准。完整来源及限制见UPSTREAM-COMPARISON。
