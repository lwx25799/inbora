## 受控试用顺序

1. 安装并启动正式包，填写现有私有目录、不初始化；核对升级备份与旧预算/暂停/未知。先核对当前绑定账号和两个许可作品，客户端显示当前实际发现源和浏览器模式。
2. 在原范围内确认可用于本次GUI试用的新事件。已有未使用样本可先只读检查；不能复用已消耗批准，不向旧未知/矛盾目标再次发送。测试者A延期的跨日/同文样本仍按用户安排，不提前催办。
3. 人工接管、输入保存；开发者关闭GUI后用显式`calibrate-client`只读校准当前准确草稿，再重开GUI。受控资格绑定目标/版本/全文/映射/浏览器模式，一小时过期，不代替批准；界面仍要求准确目标及全文逐条确认。
4. 评论/私信各自完成一条纯人工单次提交并可信回读；若发生未知，保留意图并只读核验，不为完成矩阵重发。首条可信GUI收据只提升对应通道/模式，不能覆盖其后发生的BLOCKED降级。
5. 用户在密码框输入Key并另行明确授权DeepSeek，生成同目标有限上下文建议，核对usage/累计预算、引用或修改；各通道新的外发再次逐条批准。填Key/选模式不等于付费授权。
6. 现场检查切换、暂停/恢复、急停、界面重连和重启，核对发送计数、旧未知及矛盾仍保留。Windows11独立执行安装/启动、Node/SQLite/Edge、急停与恢复；未经执行只标待验证。
