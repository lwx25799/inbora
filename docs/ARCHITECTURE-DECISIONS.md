## ADR-001：锁定「修订版路线 A+」技术栈与进程拓扑

- **状态**：已批准并锁定（2026-11-24）
- **替代 / 否决**：
  - 正式否决《V3.3 技术栈重选与迁移实施方案》与《V3.4 效果图落地迁移文档》中的 **“重写 Python Supervisor（路线 B）”**；
  - 正式否决《V3.3》首轮引入的 FastAPI REST/WebSocket、SQLAlchemy 2 / Alembic、Zustand / TanStack Query 与 M0 安装包验收门槛；
  - 正式否决《V3.4》将多模型接入重写为 Python HTTPX 的替代路线；
  - 正式否决《正式版多账号无头自动化与风控治理方案》中的 **“每账号独立 SQLite 分库”**。

### 裁决内容

采用 **修订版路线 A+**，以最小迁移风险延续既有已验证的业务权威核，同时吸收 V3.4 的协议与数据契约精髓并补齐进程隔离与原生系统桥短板：

1. **唯一业务权威（Node.js / TypeScript Core）**：保留现有 Node/TS Core（Sidecar）作为唯一业务状态机与数据库写者，统一掌管账号注册表、调度器、策略授权、预算账本、知识库与人格学习、本机 MCP 控制桥及唯一发送协调器（`SendCoordinator`）。前后端继续共享 TypeScript 契约类型（演进中抽离为纯 `contracts` 层，避免前端直接耦合后端实现）。
2. **吸收 V3.4 通信与存储精髓**：
   - **前端与核心通信**：保留 Tauri v2 + React/TypeScript + 鉴权 stdio 通道，按 V3.4 演进至 **鉴权 stdio protocol v2**（按域命令族划分，显式携带 `accountRef` 或 `GLOBAL` 作用域）；
   - **单库显式 SQL `schema4`**：坚持单一 SQLite WAL 数据库（`better-sqlite3` 预编译包）与显式 SQL 迁移，引入 `legacy_target_aliases` 映射表确保既有单账号历史目标、意图、收据与摘要零重算平滑迁移，避免跨库预算与意图事务分裂。
3. **补齐隔离与原生系统能力短板**：
   - **独立 Node Browser Worker 子进程**：进入多账号阶段（10~30 账号）后，重型 Playwright 浏览器连接器下沉至受控 Node Browser Worker 子进程（纳入同一 Windows Job Object 生命周期管理，**严禁直连 SQLite**），避免单账号浏览器事件循环或堆外内存拖垮 Core 与全局急停；
   - **Tauri Rust 原生能力桥消除 PowerShell 债**：通过 Tauri Rust 原生 Win32 能力桥（结合内存按 `mtime` 缓存）逐步替代高频冷启 `powershell.exe` 的 DPAPI 与进程资源采样调用。
4. **多平台运行时边界**：
   - 官方 API 平台（企业微信、微信客服等）与新网页平台（小红书、B站、快手等）优先在 Node 侧通过完整版 `PlatformConnector` 实现；
   - **仅对强依赖 Windows UI Automation 的个人微信原生客户端**挂接按需、无状态的 Python UIA Worker，只承担界面观察与受控动作执行，不持有数据库写权、预算裁决权或发送决定权。

### 目标进程拓扑

```text
+-------------------------------------------------------------------+
|  Tauri v2 Native Shell (Rust)                                     |
|  - 窗口管理 / 鉴权管道 / 命令白名单 / Windows Job Object          |

|  +-------------------------------------------------------------+  |
```

### 重新评估触发条件

仅当未来确认必须接入 **3 个及以上**强依赖本地原生 Python SDK（无法以 HTTP API 或 Node Playwright 替代）的核心平台，且跨进程 Worker IPC 被实测证明成为吞吐或维护瓶颈时，才允许重新开启路线 B 评审。

## ADR-003：`AGENTS.md` 既有规则分域修订

- **状态**：已批准并生效（2026-11-24）

为支持多账号与原生客户端通道演进，同时保护已验证单账号体验不退化，对原有两条全局规则做精确分域：

1. **账号在线策略分域**：
   - **单账号场景**：保持默认持续在线。正常启动自动连接既有运行目录与专属浏览器，不以普通账号暂停作为日常产品状态，不要求用户手动恢复在线；收取轮询不切换在线状态。
   - **多账号场景（大于 3 个网页账号）**：允许引入可选服务等级轮转（例如高优先账号常驻、其余账号按队列轮询唤醒），以控制本机内存与平台频控压力；单持有者锁、公平调度与资源上限继续强制执行。
2. **浏览器无头与前台通道分域**：
   - **网页浏览器连接器**：继续强制“默认无头且静音”。普通收取、发送、重连与诊断均运行在无头模式；验证码优先在原无头页面内实时弹窗人工处理，仅登录失效或本人显式查看会话时临时使用有头窗口，完成后回到无头。
   - **个人微信原生客户端 UIA**：单列为 **前台交互受限通道**，受 Windows 交互式桌面会话、锁屏与焦点约束，不套用网页无头语义；该分域严禁外溢放宽任何网页浏览器连接器的无头默认。

## ADR-004：全程不可妥协的硬安全与工程红线

- **状态**：长期有效，任何阶段迁移、重构或新平台接入均不得削弱

1. **唯一发送权威与一次提交**：所有外发入口（人工回复、AI 自动回复、本机 MCP 助手、未来多平台通道）必须经由唯一 `SendCoordinator`；提交前在 SQLite 事务中持久化 `send_intent`（绑定账号、准确目标、全文与版本、上下文摘要、接管代际、授权与幂等 `commandId`），重核同步门禁后仅执行一次提交；HTTP 200、输入框清空或点击返回成功均不构成送达证明。
2. **未知不重发**：发送结果进入 `UNCERTAIN` 或进程崩溃恢复时，绝对禁止自动重发；重启与重连只做权威只读查询与有界只读补证。
3. **急停与安全冻结不自解**：全局急停、账号变化、来源异常、平台明确停止及通道安全冻结均持久生效，重启、普通重连或仅保存配置均不得解除，必须经显式核验恢复。
4. **网页人稿零覆盖与人工优先**：人工接管代际永远高于自动回复；切换目标、后台刷新、历史滚动、模式切换与迟到异步响应绝不覆盖网页未发送人稿或客户端未保存人稿。
5. **隐私、凭据与模型隔离**：浏览器 Profile、Cookie、API Key、真实 SQLite 数据库、私人消息正文、本机缓存的真实头像、原始页面证据与诊断日志严禁进入 Git 或公开日志；Key 仅存后端内存或 Windows CurrentUser DPAPI，不进前端或明文配置；入站消息与知识/样例严格视为不可信数据，模型无浏览器、凭据或发送权限，敏感信息在预算预占前拦截，模型请求禁止自动重试。
6. **真实诚实验证**：离线/合成测试、实机验收、未验证与阻塞必须严格分列；浏览器端序列化函数须经源码 `tsx` 链与构建后 Node 链双链验证；绝不以源码提交、视觉预览基线或上游声明冒充实机通过。
7. **物理行数硬限**：所有受影响的源码、界面、样式、脚本与测试文件均不得超过 **800 物理行**（计入空行与注释）；超限文件按职责拆分，禁止压行或删除必要注释规避。
8. **安装包构建门禁**：仅在用户明确直接要求构建安装包时才执行打包；日常开发保持 Tauri 开发模式、React 热更新与 Node 按需安全重载。
9. **临时资料及时清理**：测试目录、合成数据库/Profile、隔离检出、临时脚本与缓存统一存放于 `.local`，每次测试或阶段交付前核对归属、体积与运行进程后主动清理，保留真实库/Profile、用户资料与在用工具链。

## ADR-005：阶段三轮独立审查闭环与跨阶段新会话交接纪律

- **状态**：已批准并生效（2026-11-24）

每个演进阶段（阶段 0 ~ 阶段 5）在代码与文档实现完成后，**严禁直接跳入下一阶段施工**，必须完成以下三轮独立闭环并通过退出门槛：

1. **第 1 轮独立审查 + 修复**：完成本阶段实现与基线验证后，开展覆盖架构并发、安全隐私、适配层/桌面端与文档契约的独立只读审查，对所有实锤问题完成修复与回归复验。
2. **第 2 轮独立深度审查 + 修复**：基于第 1 轮修复后的完整差异，再开展独立深度对抗审查，重点排查修复回归、同形位点漏扫（Sibling Sweep）、空心绿/零覆盖测试以及文档与契约漂移，全部修清并复验。
3. **第 3 轮只读终审（零阻塞退出）**：仅执行只读核验，逐项复核关键修改、自动化测试、隐私扫描（`check:privacy`）、物理行数（`check:source-size`）与临时目录清理，确认 **0 CRITICAL、0 HIGH、0 未决阻塞项**。
4. **交接单与跨阶段新会话接棒**：通过第 3 轮只读终审后，整理本阶段收口交接单（固定已完成基线 commit、本阶段验证覆盖与未验证限制、下一阶段目标、禁止触碰边界及首个验证命令），随后**新开会话**按交接单接棒推进下一阶段，防止长会话上下文衰减与跨阶段隐性漂移。

## ADR-006：阶段 5 品牌、视觉体系与用户体验第一准则

- **状态**：已批准并锁定（2026-11-26）
- **替代 / 清理**：正式替代并移除旧 `Inbora_UI_效果图合集/`（10 张概念 PNG）及旧版单页 HTML 原型（`Inbora原型.html` 与 `prototype/`）。

### 裁决内容

1. **品牌与视觉基准唯一化**：以 [BRAND-AND-UI-SPEC.md](../assets/brand/BRAND-AND-UI-SPEC.md)、`assets/brand/screenshots/`（7 张 2x 实渲染截图）及独立可运行前端基线 `ui-preview/` 作为阶段 5 唯一设计与组件基准。核心规格固定为：**Harbor Frame（归港方匣）** 标识套件、**暖白纸感 + 深松青**浅深双主题、**`cosscom/ui`（MIT）+ `@base-ui/react@1.9.0` + Tailwind CSS v4** 组件原语，以及全离线打包可变字体栈（`MiSans VF` + `Plus Jakarta Sans Variable` + `Inter Variable` + `JetBrains Mono Variable`，严禁外链 CDN）。
2. **9 大主工作区 + 7 个核心抽屉/弹窗**：阶段 5 工作台按「日常运营（工作台总览 / 会话中心）」「资产与智能（账号与通道 / 自动化规则 / 知识库与人格 / 多模型配置）」「治理与系统（调度与审计 / 数据统计 / 系统设置）」9 页组织，会话中心内统一承载私信直发与评论回复弹窗，并保留 `900x640` 最小窗口自适应折叠。
3. **用户体验第一准则（前台去工程术语、后台静默守底线）**：日常工作界面仅呈现客服团队关心的业务语言、清晰状态与动作，不把 `SendCoordinator`、`SQLite WAL`、`FTS5`、`DPAPI`、`leaseGen`、`sha256`、`maxRetries: 0` 等底层机制直接堆砌在日常视野；排障与审计细节收纳于折叠详情区、「调度与审计」与「系统设置 -> 故障处理」。所有安全红线由后端继续静默强制执行，绝不因界面简洁而弱化任何门禁。
4. **账号与客户头像本地采集与隐私边界**：支持在接入账号时实时同步账号头像，并按账号开关「同步采集客户头像」用于侧栏值守托盘、会话列表、双侧聊天气泡与资料卡辨识。真实运行期头像仅缓存于本地私有目录并走本机鉴权读取，**禁止作为目标放行校验依据、禁止送入模型、禁止进入 Git**。

## ADR-007：全渠道渐进演进、微信双轨、知识库与 AI 大脑升级及 8 阶段自动回复流水线

- **状态**：已批准并生效（2026-11-27）
- **适用边界**：细化 ADR-002 阶段 4 通道路线、ADR-004 第 5 条多模态与只读工具边界及 `docs/MODEL-CONTRACT.md` 路由契约；不削弱 ADR-004 任何既有安全与发送红线。

### 裁决内容

1. **终极目标与渐进隔离铁律**：
   - Inbora 终极目标为**全渠道 AI 客服工作台**，覆盖社媒私信与评论、企业微信/微信客服以及未来电商与长尾平台。
   - 按「**先深耕自媒体与企微/微信客服（抖音 / 企业微信 / 微信客服 / 小红书 / B站），后补电商与长尾平台**」顺序演进。
   - 尚未完成接入与验证的新平台或新能力必须零侵入隔离，绝不影响现有已验证场景与运行态稳定。
2. **阶段 4 微信生态双轨路线与未来扩展位**：
   - **第一批双轨并行**：同时推进**企业微信官方 WebSocket 长连接**（基于 `@wecom/aibot-node-sdk`，免公网回调部署）与**微信客服官方 API**（移植 `pawastation/wechat-kf` MIT 核心能力，支持用户自填中转或内网穿透 URL）。
   - **个人微信 4.x 后期可选**：保留为后期可选的前台纯 UIA 受限通道（受 ADR-003 前台交互分域约束，不阻塞第一批上线，**严禁进程内存扫描与 DLL 热修补**）。
   - **未来电商/长尾平台扩展位**：在 `PlatformConnector` 契约中预留副驾驶通道扩展位，具体实现形态留待后期按平台边界与实际需求选型。
3. **知识库与 AI 大脑升级**：
   - **单库检索升级与本机 ONNX 向量混合底座**：在既有单库 SQLite 上升级 FTS5（Node.js 原生 `Intl.Segmenter` 中文词级切分 + 停用词与停用 bigram 过滤 + `bm25()` 相关度打分 + 防幻觉最低相关度门槛 + 只读召回调试台），并引入本机 ONNX 向量混合检索底座。安装或初始化时先检测本机已有 ONNX 模型并执行文件完整性与 SHA-256 校验复用，缺失时自动下载；模型未就绪期间无缝降级为纯增强版 FTS5，不阻塞主程序启动与回复，且**严禁隐式 `node-gyp`**。
   - **高置信 FAQ 直出与素材图回复**：支持高置信 FAQ 精确命中直出（可选开关，免调模型、零模型额度消耗），以及在用户授权前提下附带本地素材库图片回复（仍经 `SendCoordinator` 统一提交）。
   - **按账号开关放开多模态看图**：默认关闭；仅当用户按账号显式开启后，允许将客户发来的截图或图片交由具备视觉能力的云端模型理解。固定说明、真实缓存头像与未授权预览仍禁止送入模型。
   - **白名单只读外部业务工具**：允许向模型开放经白名单登记的只读外部业务工具（查询订单、物流、库存），**严禁任何写操作、凭据访问、浏览器直控或绕过 `SendCoordinator` 的发送权限**。
   - **云端公网 HTTPS 端点红线**：继续限定仅允许公网 HTTPS 云端模型端点，不放开 `localhost`、Ollama 或私有内网网段，守住 SSRF 边界。
4. **多模型渐进四槽位路由（同步固化至 `docs/MODEL-CONTRACT.md`）**：
   - 底层模型契约支持四个逻辑槽位：`primary`（对话主模型）、`vision`（视觉理解）、`utility`（意图分类、候选 FAQ 提炼等后台轻任务）与 `embedding`（云端备用向量）。
   - 保持默认零额外配置门槛：仅配置 `primary` 即可完整运行，与既有 `m_selection` 配置完全兼容；其余槽位未配置时按规则自动降级（如无视觉能力或未开启看图时，含图消息直接转人工）。
5. **自动回复 8 阶段标准流水线与风控治理**：
   - 自动回复编排为 8 个有序阶段（资格绑定、范围与黑白名单、人工接管归属、持久化节流阀、入站安全拦截、碎片消息聚合、精细转人工与知识/FAQ 判断、出站终审与死循环保护），并支持在场景训练台只读干跑与标注回复依据。
   - **碎片消息 2–5 秒静默聚合**：合并同一会话短时间连续发来的碎片短句上下文，严格绑定最新上下文版本与人工接管代际。
   - **双层敏感词前置零扣费拦截**：合并商家自定义词表与内置平台导流/封号红线词，入站命中在预算预占与模型调用前拦截转人工（零模型扣费），出站执行二次核查。
   - **同句死循环保护**：冷却期内拦截向同一客户重复发送完全相同或高度雷同的自动回复，转为人工处理。
   - **精细转人工独立开关、归因统计与候选 FAQ 提炼**：各转人工条件（含图、售后退款投诉、议价、自定义词、知识未命中/冲突等）支持独立开关，落库统计转人工原因分布；支持纯本地从人工已解决且已确认的对话中脱敏聚类提炼待审候选 FAQ（需人工采纳，不自动生效）。
   - **SQLite 落盘三档持久化写动作节流阀**：提供保守 / 自然 / 活跃三档（及测试关闭档），冷却与滑动窗口状态持久化至单库 SQLite 跨重启生效（仅作调度节流，不做鼠标轨迹或指纹伪造）。
   - **明确否决项与发送红线**：明确**不引入**批次拆条多发与无人审批自动垫话；100% 保留 `SendCoordinator` 唯一单次提交、未知不重发与人稿零覆盖硬红线。
